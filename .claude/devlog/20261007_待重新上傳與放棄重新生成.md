# 待重新上傳與放棄重新生成

日期：2026-10-07

## 需求

1. 本機有重新生成過的已上傳單集，清單要有「需要重新上傳」的區段
2. 可以放棄重新生成的內容
3. 「再次上傳」與「放棄重新生成」只在有重新生成內容時出現，兩者成組

## 判斷條件

上傳成功會清除整個本機目錄（`upload._remove_local`），之後只有重新生成會在本機寫出 `result.json`。
因此「已上傳且本機有 `result.json`」即為待重新上傳。

不採用「本機檔案時間晚於上傳時間」：改說話者名稱、補章節、重新生成封面都會直接寫回資料庫並更新
`updated_at`，時間比較會誤判。

## 後端（`server.py`）

- 清單每筆新增 `has_local_summary`、`needs_reupload`（已上傳、本機有摘要檔、非處理中）
- 單集內容新增 `needs_reupload`（`_needs_reupload`）
- `DELETE /api/episodes/{guid}/regenerated`：清除本機目錄、回到資料庫版本
  - 只允許 `needs_reupload` 為真的單集，否則 400，避免誤刪尚未上傳的成果
  - 處理中的單集 409
  - 實作沿用 `upload.discard_audio`（已上傳才清除本機目錄）

## 前端（`web/`）

- 清單分組：處理中／**待重新上傳**／未上傳／已上傳（已上傳排除待重新上傳者）
- 結果頁中繼資料列標示「重新生成的內容尚未上傳」
- 按鈕：

  | 狀態 | 顯示 |
  |---|---|
  | 尚未上傳 | 上傳 |
  | 已上傳、有重新生成內容 | 放棄重新生成＋再次上傳（相連成組，再次上傳為綠色實心主要動作） |
  | 已上傳、無變更 | 都不顯示（整組隱藏，避免空元素多佔一格間距） |

- 「重新生成全部」完成後，已上傳的單集立即歸入待重新上傳並刷新清單
- 「放棄重新生成」先確認，完成後重新載入該集（資料庫版本）與清單
- 上傳成功後按鈕組會隱藏，先短暫顯示「已上傳／已更新」3 秒

### 按鈕狀態依集數分開（同時修正的 bug）

使用者在大H 按「重新生成」後切到歌仔調，歌仔調的按鈕也顯示「生成中」。
原因：按鈕在各集之間共用，狀態維持到請求回來；回來時還會把新摘要套到**當下顯示的那一集**畫面
（伺服器依 guid 寫檔，檔案本身沒錯，只是畫面錯）。「重新生成封面」「上傳」「放棄重新生成」同樣有此問題。

修正：以「單集＋動作」記錄進行中的動作（`busyActions`、`setBusy`、`renderBusyButtons`），
切集時按鈕顯示該集自己的狀態；回應到達時只有仍在同一集才更新畫面，否則只刷新清單。

## 驗證

- 後端：大H 那集 `needs_reupload` 為真、其他已上傳集為假；對一般已上傳集呼叫放棄回 400
- 放棄流程：另以程式產生一組完整的「重新生成」檔案（博音 EP242，不碰資料庫、不呼叫模型），
  從介面實際點擊放棄：確認框正確、清單由「待重新上傳 2」回到 1、摘要回到資料庫版本、按鈕消失；
  測試檔已清除。使用者大H 那集的真實重新生成內容未動
- 按鈕狀態：攔截 `/regenerate` 以假結果延遲回應（不呼叫模型），
  在大H 按下→切到歌仔調→切回大H→結果回來，各步驟按鈕與摘要皆正確
- 按鈕成組：兩種狀態各截圖確認版面
