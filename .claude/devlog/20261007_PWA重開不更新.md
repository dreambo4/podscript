# PWA 重開不更新

日期：2026-10-07

## 問題

手機章節功能部署後（`5c16ad4`、`72b6a88`），使用者的 PWA 重開好幾次仍是舊版。
版本號（`stamp-assets.py`）兩次部署前都有更新，線上 `index.html` 也確認是新版號。

## 原因

- Firebase Hosting 對 `/`、`/index.html` 的預設標頭是 `Cache-Control: max-age=3600`
- `sw.js` 處理導覽請求時用 `fetch(request)`，預設會先查瀏覽器 HTTP 快取；
  `index.html` 還在 1 小時效期內就直接拿舊的，根本沒連到伺服器
- 舊 `index.html` 引用的是 `app.js?v=舊版號`，剛好在 SW 快取裡，整套都是舊版
- 版本號寫在 `index.html` 裡，`index.html` 本身被快取時版本號機制失效

`curl -I` 實測：`/`、`/index.html`、`app.js?v=…`、`style.css?v=…` 皆為 `max-age=3600`，只有 `sw.js` 是 `no-cache`。

## 修正

- `sw.js`：導覽請求改為 `fetch(request.url, { cache: "no-cache", credentials: "same-origin" })`，
  強制向伺服器確認（有 ETag，未變動時回 304，成本低）。
  navigate 模式的 Request 不能帶 RequestInit，故以網址重新發出
- `firebase.json`：`/`、`/index.html` 加 `Cache-Control: no-cache`

`app.js`／`style.css` 維持 `max-age=3600`：網址帶版本號，內容變了網址就變，可以放心快取。

## 生效時機

使用者手機目前跑的是舊 SW。下次開 App 時瀏覽器檢查 `sw.js`（`no-cache`）發現新版，
新 SW 立即接手（`skipWaiting` + `clients.claim`），但這一次的頁面已由舊 SW 載入；
**可能要再開一次**才會看到新版。最慢等瀏覽器快取的 `index.html` 過期（1 小時）也會恢復。

## 驗證

- `sw.js` 語法檢查、`firebase.json` JSON 格式檢查通過
- 部署後以 `curl -I` 確認 `/`、`/index.html` 為 `no-cache`
- 實機行為需使用者確認（headless Chrome 無法重現 iOS PWA 的快取狀態）

## 異動摘要

- `mobile-web/sw.js`：導覽請求不使用 HTTP 快取
- `firebase.json`：`/`、`/index.html` 改為 `no-cache`

## 影響範圍

- 手機 PWA 與瀏覽器開啟 podscript.web.app 時的更新速度；離線開啟行為不變

## 建議 commit 訊息

```
fix: PWA 開啟時不使用瀏覽器快取的 index.html，避免重開仍是舊版
```
