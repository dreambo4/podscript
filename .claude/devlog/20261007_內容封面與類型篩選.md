# 內容封面與類型篩選

日期：2026-10-07

## 需求演進

1. 手機卡片右下角加 1/4 圓類型色塊（音檔／影片／文章），並加進篩選條件
2. 使用者覺得畫面整體太花，要多種設計比較 → 做了 A～F 六種方案的比較頁
3. 改成「依每集內容畫封面 icon、不含文字」：Claude 先手畫 11 集試做
4. 決定由摘要模型每集現畫；卡片定案為方案 E（類型在節目名稱前、標籤改灰色純文字 #）
5. 本機結果頁可單獨「重新生成封面」；本機左側清單改為相同卡片樣式（不含收藏）

## 封面

### 規格

- `{"svg": "...", "color": "#rrggbb"}`；svg 為 viewBox 0 0 48 48 的內部元素
- 線條插圖，顏色一律 `currentColor`，前端依 `color` 與深淺色主題上色
  （淺色：底色混 15%；深色：底色混 24%、線條混入 45% 白提亮）
- 不含任何文字

### 產生

- `src/podscript/cover.py`：`COVER_RULES`（兩個 prompt 共用）與 SVG 白名單過濾 `normalize`／`sanitize_svg`
- 摘要 prompt 新增第 5 項 `cover`，與摘要同一次 `claude -p` 呼叫，不另開呼叫
- `COVER_PROMPT`：只依標題、摘要、標籤重畫，不送逐字稿；`POST /api/episodes/{guid}/cover`
- 封面畫壞或過濾後為空時為 None，不影響摘要

### 安全

模型輸出的 SVG 不可信，以白名單重建：只留 path／circle／ellipse／rect／line／polyline／polygon／g，
屬性逐一驗格式，fill／stroke 只允許 none／currentColor；拒絕 `<!`（DOCTYPE／ENTITY）。
手機前端以 DOMParser 再過濾一次；外層 `<svg>` 給預設屬性（fill none 等），避免被濾掉屬性的元素變黑色實心。

測試：script、onclick、`<a>`／`<image>`、foreignObject、text、d 夾帶引號、url() 顏色皆被擋下；
手機端以惡意資料實測無任何 alert 觸發。

### 資料

- DDL（使用者執行）：`alter table episodes add column cover jsonb;`
- 上傳、從資料庫還原、`update_episode` 帶上 `cover`；`FETCH_COLUMNS` 多一欄後時間戳索引順移
- 再次上傳時新封面為空則保留原本的：`cover = coalesce(excluded.cover, episodes.cover)`
  （於交易中實測後 rollback）
- 既有 11 集寫入 Claude 手畫封面（經同一過濾器，UPDATE）；EP239 由使用者指定換回手畫版

### 模型實測

使用者按「重新生成封面」產生的 ADHD 封面（大人牽小孩＋分心短線）與大H 那集（啞鈴）皆無文字、風格一致。

## 類型篩選

- 手機後端 `list_episodes` 新增 `kind`：audio＝YouTube 與文章以外、video＝youtube、article＝article
  （正式資料：6＋3＋2＝11，無遺漏或重疊）
- 篩選面板新增「類型」單選；已套用的篩選列顯示對應標籤

## 卡片樣式

- 手機：頻道色方塊改封面；無封面時灰底類型 icon；類型在節目名稱前；標籤灰色 `#文字`
- 中途做過的右下角 1/4 圓色塊（含淺色主題外框被色塊吃掉的修正）最終移除
- 本機左側清單：同樣卡片、不含收藏；側欄加寬至 340px、鋪淺底色、卡片維持白色；
  只保留「處理中 xx%」「未生成摘要」「未完成，點擊繼續」狀態；meta 每段不斷行
- 本機清單 API 新增 `platform`、`cover`；處理中尚未取得節目資訊時以 `resolvers.platform_of(url)` 判斷平台
- 修正：狀態列改 block 後轉圈動畫寬度變 0 成一根細線 → 改回 flex
