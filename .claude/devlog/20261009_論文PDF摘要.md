# 論文 PDF 摘要

日期：2026-10-09

## 背景

待辦第 8 項。上一步（`20261008_論文PDF上傳Storage.md`）只做了原檔上傳 Storage；
這次把論文接進處理流程：上傳 PDF → 擷取全文 → 摘要、心智圖、標籤、封面 → 上傳資料庫，手機可瀏覽。

使用者決定：來源欄位（`podcast_name`）填期刊名稱；翻譯這一輪不做；論文摘要可以比 Podcast 長。

## 做法

### 全文擷取（`resolvers/paper.py`）

PDF 只有一行行文字與座標，以 pypdfium2 逐字取字級（寬鬆字框高度）、粗體／斜體（字重與字型名稱）、位置：

- 頁首頁尾：頁面上下 10% 內、多頁重複（數字視為相同）的行，與單獨的頁碼
- 論文標題：第一頁上半部字級最大、同字型的連續行；期刊刊頭字大但太短，跳過
- 首頁資訊區：摘要（Abstract）之前的作者、單位等，不算章節
- 章／節標題：短行、不以句號逗號結尾、比內文大或粗體或斜體，且對齊欄左緣或在欄內置中；
  下一行小寫開頭、結尾是連接詞、含逗號名單、只有符號者都不算。字級最大的一級為章（`h1`），
  其餘與「2.1」編號、斜體標題為節（`h2`）
- 表格：「Table N.」標題後的表格列（欄距大於一個字寬），或連續三行以上的表格列；每列一行，
  標題在表格下方（電腦科學論文常見）時接回前一個表格
- 段落：依行距、縮排、上一行是否寫滿且以句號結尾分段。pdfium 遇到行尾斷字（U+FFFE）不換行，
  一行可能跨兩個視覺行，因此另記最後一個視覺行的右緣
- 圖內文字：遠小於內文的短行、只有數字的行（座標軸刻度）、連續三行以上不成句的短行
- 參考文獻：References 之後跨段收集，依編號切成一筆一段（`ref`）；之後再出現章標題（附錄）即結束

以三份不同排版的 PDF 實測（BMC 雙欄、CVPR 雙欄、PLOS 單欄＋側欄），每份擷取不到 1 秒。
已知限制：數學式為亂碼（字型對應錯誤）、複雜表格（含大括號的架構表）會亂、圖說偶爾被當成節標題。

### 流程與資料

- 每個段落、標題、表格、參考文獻存成一個片段，`DiarizedSegment` 新增 `kind` 欄位（只有論文寫入，
  既有資料格式不變）；與文章共用「段落定位」的格式，不需 DDL
- 章節取自章標題（`pipeline.paper_chapters`），不呼叫模型；章標題不到兩個時改用節標題
- 摘要 prompt（`PAPER_PROMPT`）：約 400 字，依序寫研究問題、方法、主要發現、限制；心智圖第一層同此結構；
  同一次呼叫讀出 `meta`（標題、期刊、第一作者、發表日期），套用到單集的標題、`podcast_name`、`published_at`
- 送模型的全文不含參考文獻
- PDF 原檔存在單集目錄 `source.pdf`；按「上傳」時先傳 Storage（失敗就不寫資料庫），之後本機目錄照常清除
- 刪除已上傳的論文時一併刪除 Storage 原檔

### 介面

- 本機：頂部「上傳論文」按鈕；結果頁「開啟 PDF 原檔」（本機檔或從 Storage 取）；原文顯示章節、節標題、
  表格（等寬字、可橫向捲動，表格標題獨立成段）、參考文獻；下載 Markdown 也依類型輸出
- 手機：論文 icon、篩選面板「論文」、原文分頁同本機的顯示方式；手機後端沒有 Storage 金鑰，不提供原檔

## 驗證

- 範例論文（Springer／BMC，17 頁）實際跑完摘要（opus）：期刊 Nutrition & Metabolism、日期 2009-05-14、
  11 章、4 個表格、47 筆參考文獻；摘要依四段結構，約 400 字
- 本機頁面以 Playwright 檢查：開啟 PDF 原檔 200、章節 11、節標題 24、表格 4、參考文獻 47、無 JS 錯誤
- 非 PDF 回「不是 PDF 檔」；沒有文字的 PDF 回掃描檔提示
- 上傳資料庫與 Storage、手機端顯示：待使用者同意後驗證
