# 心智圖手機縮圖與全螢幕操作

日期：2026-09-26

## 背景

使用者回報：心智圖可以無限往上下左右滑動。

實際查 markmap-view 0.18 原始碼後，問題有三層：

1. **平移無邊界**：d3-zoom 預設 `translateExtent` 無限大，圖能被拖到整張消失，
   且沒有「回到原位」的入口，只能重新整理
2. **縮放無上下限**：`scaleExtent` 也沒設
3. **手機捲動被攔**（使用者沒提、但影響更大）：心智圖容器 420px 約佔半個手機畫面，
   d3-zoom 會攔下單指觸控，手指一碰到圖頁面就捲不動，只能找圖外空白處滑

使用者表示**手機是主要檢視工具，不希望難用**，所以第 3 點才是重點，
只加邊界（第 1、2 點）不夠。

## 決策過程

提了兩個手機方案：

| 方案 | 做法 | 取捨 |
|---|---|---|
| **A 縮圖 + 全螢幕** | 頁面內唯讀縮圖，點擊進全螢幕操作 | 小框本來就看不清寬圖；全螢幕可轉橫 |
| B 雙指操作 | 單指捲頁面、雙指拖圖（類似 Google 地圖嵌入） | 改動小，但 420px 小框裡雙指易誤觸 |

先做示意頁讓使用者在手機上實際比較「現況／改善後」：
https://claude.ai/artifact/V2EAMaebmfCVerV4jdLazC

示意頁第一版用虛構的 3 層小圖，使用者要求改用一集實際的大張心智圖
（外泌體那集，guid `9802b168-f070-4ae5-b5f8-b01508c5ca74`，9 個分支、53 個節點）。
換成大圖後暴露三個問題，都在示意階段修掉才進正式實作：

1. **「留 80px 在畫面內」的邊界規則對大圖無效**：外框角落常沒有節點
   （樹狀圖右下角是空的，最右邊的節點在上方、最下面的節點在中間），
   拖到極限時留下的那一角是一片空白。
   → 改為**外框至少佔畫面一半寬、一半高**（內容比畫面小時整張留在畫面內）
2. **縮圖 300px 太矮**：最後一個分支被切掉 → 改回 420px，並在渲染 600ms 後再 fit 一次
   （首次 fit 時展開動畫與文字量測未完成）
3. **縮圖底部的提示文字蓋住節點** → 拿掉，只留右上角「全螢幕」按鈕

使用者看過示意頁後定案 **方案 A**。電腦版只加邊界，維持直接在頁面上操作。

## 踩到的坑

1. **`zoom.transform` 不經過 `constrain`**
   markmap 內建的觸控板捲動平移（`handlePan`）用的是 `svg.call(zoom.transform, t)`，
   d3-zoom 的 `transform` 不套用 `constrain`，所以只設邊界的話，觸控板捲動還是能拖出去。
   `translateBy` / `scaleBy` 與拖曳、捏合手勢才會套用。
   → 關掉 `pan`，自己註冊 `wheel.bounded` 改走 `translateBy`

2. **非 Mac 的滾輪是縮放，不能同時平移**
   markmap 的 `scrollForPan` 預設只在 UA 含 `Macintosh` 時為 true。
   非 Mac 時 d3 會把滾輪當縮放，自訂 wheel 若也平移會兩個一起動。
   → 自訂 wheel 只在 `mm.options.scrollForPan` 為 true 時作用

3. **markmap 載入時序**
   markmap 是 ESM 從 CDN 載入，`app.js` 是一般 script。
   API 回得比 CDN 快時，詳情頁會停在「（心智圖元件尚未載入）」，且不會自己恢復。
   這是原本就存在的問題，用 Playwright 攔 API 回傳（瞬間回應）時才重現。
   → 改由 module 載入後 dispatch 事件補畫

4. **`hidden` 被 `display: flex` 蓋掉**（示意頁）
   artifact 沒有專案的 `[hidden] { display: none !important; }`，
   overlay 的 `display: flex` 讓它一直疊在畫面上。專案內已有這條規則，正式實作不受影響。

## 驗證

Playwright，手機 390×844、`has_touch`、`is_mobile`、`service_workers='block'`，
登入資訊寫 localStorage、`/api/**` 攔截回傳外泌體那集實際的心智圖：

| 項目 | 結果 |
|---|---|
| 在縮圖上以觸控往上滑 | 頁面捲動 602 → 350 |
| 全螢幕初始可見節點 | 53 / 53 |
| 單指往四個角各拖 3000px | 可見 21～33 個節點，不會全空 |
| 重置 | 恢復 53 |
| 關閉鈕／Esc／換頁 | 皆退出全螢幕、body 解除捲動鎖定 |
| 點縮圖空白處 | 進全螢幕 |
| 深淺色截圖 | 按鈕與節點文字皆清楚 |
| JS 錯誤 | 無 |

電腦版（`web/mindmap-render.js` 經 8420 服務，900×520 容器）：

| 環境 | 拖 5000px | 滾輪連捲 | 縮放倍率 |
|---|---|---|---|
| Mac UA（捲動＝平移） | 可見 28 | 可見 28～30 | 不變 |
| Windows UA（滾輪＝縮放） | 可見 28 | 縮到 0.25／放到 4 即停 | 放到 4 倍仍可見 5 個 |

> 注意：在 Mac 上跑的 headless Chromium 預設 UA 含 `Macintosh`，
> 不指定 UA 就測不到非 Mac 行為。第一次兩組結果完全相同才發現。

**未驗證**：真實手機上的觸控手感（CDP 模擬的觸控事件無法代表實機），待使用者實測。
