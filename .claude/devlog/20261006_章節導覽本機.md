# 章節導覽（本機）

日期：2026-10-06

## 背景

todo #3。逐字稿動輒一兩小時，想跳到某個話題只能一路往下捲。
由模型依逐字稿切出章節，結果頁列目錄、可點擊跳轉，捲動時目前章節標題固定在頂端。

## 已定案（使用者決定）

1. 章節跟摘要同一次 `claude -p` 產生，不另開一次模型
2. 章節數依節目長度：約每 8 到 12 分鐘一章，至少 3 章、最多 15 章
3. 結果頁同時有「目錄」與「逐字稿內的章節分隔標題」，標題捲動時 sticky 置頂，進入下一章時被推走換成下一章
4. 舊集數另用只產生章節的 prompt 補上，不動摘要、心智圖、標籤；約 3 萬 token／集。
   原定前端放「補上章節」按鈕逐集觸發；驗收前使用者改決定：既有 8 集由 Claude 以端點一次跑完，**前端不留按鈕**，
   端點與 Bruno 保留供個別重跑
5. 文章不做章節
6. **DDL 提前**：上傳後本機檔案會清除，舊 Podcast 集數全部只在資料庫，
   不加欄位的話章節一上傳就消失。使用者同意現在就加：
   `alter table episodes add column chapters jsonb not null default '[]'::jsonb;`
   手機端顯示仍留到第二階段

## 批次後發現的問題（2026-10-07）

**YouTube 作者章節 vs AI 章節**
- 3 集 YouTube 只有 `yt_WFGoFKxiOoQ` 有作者章節（10 章），另 2 集為 0
- 對照該集，AI 有 3 章標題與段落內容對不上；使用者判斷 AI 標題較好，唯一缺點是沒標出業配
- 使用者決定：**以 AI 章節為準，不用 YouTube 作者章節**

**對齊 bug：每章都被往前拉一段**
- 用該集重跑並印出模型原始輸出，模型給的時間（03:50、07:17…）與逐字稿時間戳完全一致，是對的
- 原因：`transcript.txt` 的時間戳捨去小數（`_timestamp` 用 `int`），模型照抄 03:50 = 230 秒，
  但段落實際從 230.62 秒開始；`bisect` 拿 230 比 230.62 → 判定還沒到這段 → 對到前一段
- 修正：`normalize` 改用捨去小數後的段落開始時間比對
- 首次批次的 8 集全部受影響；使用者選擇重跑（不採「往後移一段」的推測修補）

**業配章節**
- `CHAPTER_RULES` 加入：有業配／廣告／贊助段落時獨立成一章，標題以「業配：」開頭並寫出品牌；
  沒有就不要產生，一般討論提到品牌不算業配
- 使用者提醒「不是每一集都有業配」，故明寫「沒有這類段落就不要產生」避免模型硬湊

**長段落（使用者決定先不處理）**
- 段落依換人講話切，單人旁白的 YouTube 段落很長（妲己那集平均 135 秒、最長 7.6 分鐘）
- 章節只能對齊到段落開頭，長段落時章節位置精度受限


## 實作重點

**章節檢查（`chapters.normalize`）**
- 時間接受 `hh:mm:ss` 與 `mm:ss`（沒寫小時時分鐘可超過 60）
- 格式錯誤、超過節目長度 5 秒以上、對齊後比前一章早或落在同一段 → 只丟該章
- 對齊到「不晚於該時間的最近一段」，存該段的 `start` 秒數；前端以 `start` 相等找段落
- 第一章不在第一段時補「開場」；剩不到 2 章整組不用
- 摘要生成時章節失敗不影響摘要；「補上章節」時章節全部不合格回 502

**補上章節** `POST /api/episodes/{guid}/chapters`
- 用 `CHAPTERS_PROMPT`（與摘要 prompt 共用 `CHAPTER_RULES`），只產生章節
- 本機有 `result.json` 時寫入；已上傳的同時 `update_episode(chapters=...)` 寫回資料庫（與說話者改名相同，不需再次上傳）
- 文章、尚未產生摘要回 400

**上傳**：`UPSERT_SQL`、`build_payload`、`FETCH_COLUMNS` 加 `chapters`；`fetch_all` 的時間欄位 index 由 13/14 改 14/15

**sticky 置頂**：每章包 `<section class="chapter">`，`.chapter-title { position: sticky; top: var(--topbar-h) }`，
純 CSS，標題只在所屬 section 內固定，下一章到頂時被推走；`scroll-margin-top` 讓目錄跳轉不被頂部列蓋住；列印時改回 static

## 驗證

假資料 `audio/test-chapters-demo`（80 段、40 分鐘、4 章，測完已刪）＋ 另開 8431 埠的本機服務，
以 headless Chrome（DevTools 協定）在 1200 與 420 寬截圖並量測標題位置：

| 情境 | 結果 |
|---|---|
| 捲到第 2 章中段（420 寬） | 第 2 章標題 top = 108（窄螢幕頂部列高度） |
| 第 3 章標題在頂部列下 25px | 桌面：第 2 章被推到 12、第 3 章在 86；窄螢幕：59／133，不重疊 |
| 點目錄第 4 章（桌面） | 標題 top = 61（頂部列高度），未被蓋住 |
| 已上傳的 YouTube 集數 | 從資料庫讀回 `chapters: []`（當時仍有按鈕，之後拿掉；無章節時章節區隱藏） |
| `normalize` 單元測試 | 倒退、同段、格式錯誤、超出長度、補開場、不足 2 章皆符合預期 |

未實測：實際呼叫 `claude -p` 產生章節（會耗額度，留給使用者驗收時按）
