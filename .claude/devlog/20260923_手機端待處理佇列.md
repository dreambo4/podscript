# 手機端待處理佇列 + PWA 完整支援

日期：2026-09-23

## 需求
1. 手機端貼網址 → 存進 DB 暫存 → 回家在本機端手動觸發下載與轉錄
2. 手機端完整支援 PWA 顯示
3. css/js 帶時間戳強制瀏覽器更新

## 設計決策

### 1. 手機端只驗證「是合法 http(s) 網址」，不檢查平台
原先設計為檢查 `podcasts.apple.com` + `/id` + `?i=`，作業中依使用者要求改為
通用 URL 驗證。理由：未來要支援多平台，解析責任在本機端 resolver，
平台擴充時不必同步改動手機端。

驗證內容（`mobile-backend/app/routers/queue.py:_validate_url`）：
- scheme 限 http/https —— 擋下 `javascript:`、`data:` 等進了 DB 後
  若被放進 `<a href>` 就成為 XSS 入口的 scheme
- 須有 netloc
- 長度上限 2048（url）/ 200（note）

### 2. 防注入
- **SQL injection**：全部走 psycopg 參數化查詢（`%s`），原本就無風險
- **XSS**：mobile-web 原本沒有 `escapeHtml`，本次新增並套用在
  待處理項目的 url／note 上（使用者直接輸入、風險最高的兩個欄位）

### 3. 本機端每筆一顆「開始處理」按鈕，手動觸發
與現有「上傳是手動觸發」一致（spec §11 決策 10），
不引入佇列排程或狀態機（spec §4.4）。

### 4. 佇列結案時機在「上傳成功」而非「轉錄完成」
轉錄完成但摘要不滿意時會重新生成，此時該集尚未真正完成；
上傳代表使用者已認可，才是結案的正確時點。

### 5. 快取破除改用內容雜湊而非時間戳
使用者要求「帶時間戳」，實作改用 **內容 sha256 前 12 碼**，理由：
- mtime 會被 git clone／checkout 刷新，內容沒變卻產生新版本 → 使用者白白重抓
- 戳章腳本本身會改寫 index.html，若 sw.js 的版本取自 mtime，
  每次執行都會產生新版本，永遠不收斂（實測確認過此 bug）

兩端做法不同：
- **web/（本機端）**：FastAPI 在回應首頁時注入，存檔即換網址，無需手動動作
- **mobile-web/（Firebase Hosting）**：純靜態，部署前跑 `scripts/stamp-assets.py`

## 異動摘要

### 資料庫（DDL 由使用者執行）
- `supabase/schema.sql`：新增 `queue` 表
  - `status` 加 CHECK 約束（避免應用層寫錯字靜默存入）
  - `added_by` 加 `on delete set null`（刪除使用者不該被 FK 擋住）
  - `url`／`note` 加長度約束，與後端上限對齊
  - partial unique index `where status = 'pending'`：同一網址只允許一筆待處理，
    結案後可再次貼上。已實測 `on conflict do nothing` 與 partial index 的組合行為正確

### 手機端後端 mobile-backend
- 新增 `app/routers/queue.py`：`POST /api/queue`、`GET /api/queue`、`DELETE /api/queue/{id}`
  - 入列前先查 `episodes.source_url`，已處理過的直接擋下（409）
  - 重複貼同一網址回傳既有那筆，前端視為成功而非錯誤
- `app/main.py`：註冊 queue router

### 手機端前端 mobile-web
- `index.html`：列表頁新增可收合的「待處理」section（依使用者要求改為
  列表內 section，非獨立畫面）；新增 `ic-plus`／`ic-trash` 圖示
- `app.js`：新增 `escapeHtml`、待處理區的載入／新增／移除邏輯、
  Service Worker 註冊、`queue=open` 捷徑參數處理
- `style.css`：待處理區樣式；**PWA safe-area** —— topbar、#content、
  group-heading、scrubber 都補上 `env(safe-area-inset-*)`
- **新增 `sw.js`**：只快取靜態外殼，API 一律走網路
  （資料會變；且回應依 JWT 而異，快取會跨帳號洩漏收藏狀態）
- `manifest.json`：加 `scope`、`orientation`、`shortcuts`（長按圖示直達待處理／收藏）
- `firebase.json`：sw.js／manifest.json／config.js 設 `no-cache`，
  否則改版推不出去；icons 設 7 天快取

### 本機端 src/podscript
- `upload.py`：新增 `fetch_queue`／`annotate_queue_item`／`resolve_queue_item`／
  `remove_queue_item`。前三者查詢失敗回傳空值而不拋例外 —— 佇列是附屬功能，
  不該讓資料庫連不上擋住列表頁或中止轉錄
- `server.py`：新增 `GET /api/queue`、`DELETE /api/queue/{id}`；
  `ProcessRequest` 加 `queue_id`（解析後回填標題）；
  上傳成功後呼叫 `resolve_queue_item` 結案；
  新增 `index()` 路由注入資源版本
- `web/index.html`／`app.js`／`style.css`：sidebar 頂端新增「手機待處理」區

### 工具
- 新增 `scripts/stamp-assets.py`：mobile-web 部署前的資源戳章（含 `--check` 模式）

## 影響範圍
- **新增功能，不影響既有流程**：未執行 DDL 時，`fetch_queue` 查詢失敗回傳空列表，
  待處理區自動隱藏，其餘功能不受影響
- PWA 的 safe-area 改動會影響**所有**手機端頁面的版面（topbar 變高、內容區留白）
- 本機端首頁改由 `index()` 提供，不再直接由 StaticFiles 的 html=True 處理

## 待使用者執行
1. **執行 DDL**（見下方 SQL）
2. 部署前跑 `python3 scripts/stamp-assets.py`
3. 部署 mobile-web 到 Firebase Hosting、mobile-backend 到 Railway
4. 重啟本機端 `./run.sh`
