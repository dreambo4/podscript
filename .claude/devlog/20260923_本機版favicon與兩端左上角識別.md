# 本機版 favicon 與兩端左上角識別

日期：2026-09-23

## 背景

`web/`（本機版）完全沒有 favicon，`mobile-web/`（手機版）已有一組完整的
favicon 與 PWA icons。兩邊 `<title>` 都是 `podscript`、左上角都是純文字 `<h1>podscript</h1>`，
在瀏覽器分頁列上**完全無法分辨誰是誰**。

使用者要求：找 Gemini 幫本機版設計 favicon，兩套主頁左上角也改成可一眼辨識。

## 決策過程

### 第一輪（作廢）
原本委託 Gemini 畫 6 組「成對」提案（本機 + 手機各一）。
使用者中途修正需求：**手機版不動**，只畫本機版，要「有關聯但可明顯辨識」。

### 第二輪：6 個本機版提案
沿用手機版的深藍底 `#0F172A` 與三色（青 `#06B6D4`／藍 `#3B82F6`／桃紅 `#EC4899`）作為關聯手法。
使用者選定 **04 運算引擎**（六角形框 + 三色垂直音軌），但指出
「六角外框跟底色太近」。

實測確認：六角框 `#334155` 對底色 `#0F172A` 對比僅 **1.72:1**，16px 下必然糊掉。

### 第三輪：8 款六角變體
沿著六角方向重做，每款用不同手法解決外框對比。
Gemini 產出 6 款，另有 2 款是 Claude 發現缺陷後補的修正版：

| # | 名稱 | 六角對比 | 備註 |
|---|---|---|---|
| 01 | 螢光線框 | 17.06:1 | |
| 02 | 實心模組 | 17.06:1 | ⚠ 青色音軌疊白六角僅 2.32:1 |
| 03 | 破框輪廓 | — | ⚠ 深色分頁列上對比 1.11:1，整顆消失 |
| 04 | 三色分段框 | 4.85–7.35:1 | |
| **05** | **反轉傳送門** | **17.06:1** | **← 定案** |
| 06 | 重型裝甲框 | 3.75:1 | |
| 02b | 實心模組（修正） | 3.98–6.03:1 | Claude 補 |
| 03b | 破框輪廓（修正） | 6.28:1 | Claude 補 |

**定案：05 反轉傳送門** — 亮底 `#F8FAFC` + 深藍實心六角 `#0F172A` + 三色垂直音軌。
亮色底與手機版的深色底形成最大反差，在分頁列上一眼可分。

## 過程中抓到的兩個缺陷

Gemini 的 `HEX-README.md` 宣稱 6 款「16px 辨識度皆極高」，但用 WCAG 相對亮度
公式實算後發現兩個會實際壞掉的問題（非美感問題）：

1. **02 實心模組**：六角框本身對比 17.06:1 沒問題，但青色音軌疊在白六角上只有
   **2.32:1**，三條音軌會糊成一片 → 音軌等於消失，而音軌正是「三位說話者」的語彙載體。
2. **03 破框輪廓**：拿掉了滿版底色塊，六角形本身是深藍 `#0F172A`，
   在深色分頁列 `#202124` 上對比 **1.11:1** → 整顆 favicon 消失。
   這違反 favicon-design skill 規範第 3 條「自帶背景色塊確保深淺底皆可辨識」。

兩款原版都保留在提案頁供對照，未逕行刪除。

## 異動摘要

### 新增
- `web/favicon.svg` — 本機版 favicon（05 反轉傳送門）

### 修改
- `web/index.html`
  - `<title>` 改為 `podscript · 本機`
  - 加上 `<link rel="icon" type="image/svg+xml" href="favicon.svg">`
  - 左上角 `<h1>` 改為 `.brand`：inline SVG 圖示 + `podscript` + `本機` 標籤
- `web/style.css`
  - 新增 `.brand-mark` / `.brand-name` / `.brand-env` 樣式
  - `.brand-mark` 尺寸 **32px**（使用者要求放大，初版為 24px）
  - 窄螢幕規則由 `.topbar h1 { display: none }` 改為只隱藏文字、保留圖示
    （圖示現在是識別主體，整個收掉會失去辨識）
- `mobile-web/index.html` — 左上角同樣改為 `.brand` 結構，標籤為 `手機`
- `mobile-web/style.css` — 對應的 brand 樣式，`--muted`／`--line`／`--card`
  皆取自既有 token，深色主題自動跟著變
  - `.brand-mark` 尺寸 **30px**（使用者要求放大，初版為 22px）。
    上限受 topbar 固定高度約束：`--topbar-h: 56px` − padding-block 20px = 可用 36px，
    30px 留 6px 餘裕。**不可再放大到超過 36px**，否則會撐破 topbar，
    而 `--topbar-h` 被多處 sticky 定位（`top: calc(var(--topbar-h) + ...)`）引用，
    撐破會連帶造成篩選列、分類列的吸頂位置錯位
- `mobile-web/sw.js` — `CACHE_VERSION` 由 `scripts/stamp-assets.py` 自動更新

`mobile-web/favicon.svg` 與 PWA icons **未更動**（使用者指定手機版不動）。

## 影響範圍

- **本機版**：分頁列出現 favicon（原本沒有）；左上角多出圖示與「本機」標籤
- **手機版**：左上角多出圖示與「手機」標籤；favicon 本身不變
- **PWA**：`sw.js` 的 `CACHE_VERSION` 已更新，使用者下次開啟會重抓外殼
- **無後端異動**，`src/` 未動。本機版 `web/` 由 `server.py` 的 StaticFiles 掛載，
  `favicon.svg` 自動可被服務，無需註冊

## 驗證

- 8 款提案皆通過：XML 合法、`viewBox="0 0 32 32"`、座標與**描邊外緣**未溢出、
  皆自帶圓角背景色塊、stroke-width ≥ 2.5
- 對比度以 WCAG 相對亮度公式實算（非目測）
- `python3 scripts/stamp-assets.py --check` → 版本已是最新
- headless Chrome 放大截圖檢視四種狀態：本機版桌機 1100px／本機版窄螢幕 420px／
  手機版淺色／手機版深色，皆正常

  > 截圖過程中一度以為本機版文字消失，實為測試 iframe 寬度 760px 低於
  > 斷點 800px 所致（即窄螢幕的預期行為），改用 1100px 重截後確認正常。
  > 記錄於此以免日後誤判為 bug。
